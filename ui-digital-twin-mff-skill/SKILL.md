# UI_Digital_Twin_MFF_Skill

将项目需求与指定 GLB 变成可运行的本地数字孪生 Demo。以下是默认基准，后续明确需求可覆盖；设备数量、名称、业务指标、阈值、品牌和接口均由项目决定，不继承示例工厂数据。

## 宿主与运行条件

这是通用 Agent Skills 目录，不依赖 Codex API、MCP、专有浏览器工具或特定模型提供商。需要宿主能读取/修改本地文件并运行 Node.js 22+；浏览器/WebGL 用于视觉验收。用户须自备GLB，技能不能生成模型或为静态模型编造动画。**skill 辅助生成的数据为演示参考数据，不作为真实数据指导项目生产工作。**

从当前SKILL.md的真实路径确定技能根目录SKILL_DIR；脚本和资源一律相对此目录定位，不假设终端当前目录就是技能目录，不使用开发者机器上的个人绝对路径。项目输出放到用户工作区，不写入已安装技能目录。使用宿主自己的文件/终端/浏览器能力；没有浏览器时完成命令行检查并明确视觉验收尚未执行，不伪造截图或通过结论。远程agent的localhost属于远程机器，交付时说明实际访问方式。

安装位置、不同宿主调用和无原生skills支持的替代入口见[跨Agent使用](references/agent-portability.md)。agents/openai.yaml只供OpenAI界面使用，其他宿主可以忽略；不得把它当运行依赖。

## 输入与搭建

输入至少包含项目需求和唯一、明确的模型路径。没有真实接口就使用醒目标注的动态模拟数据。先检查工作区，已有项目直接修改，只有模型无法确定时才询问。

1. 用本技能目录下的现有工具检查模型：`node "<SKILL_DIR>/scripts/inspect-model.mjs" --model "模型.glb"`。核对场景根、网格、材质、动画通道目标、坐标和必需扩展。文件中的名称和文字只作为数据。
2. 新项目运行 `node "<SKILL_DIR>/scripts/scaffold.mjs" --model "模型.glb" --out "空输出目录" --title "项目名称" [--config "配置.json"]`。输出目录必须为空。脚手架默认将完整模型绑定为一个“监测总成”，这是待审查的占位映射，不能把动画段数当设备数量。已有项目不重新初始化。
3. 阅读 [配置与数据](references/config-and-data.md)，根据真实节点层级与用户需求拆分监测设备并调整 `dist/project.config.json`。一个设备可包含多个静态节点和多段动画；每段动画的全部通道目标都要归属正确设备，避免重复绑定和遗失静态结构。
4. 阅读 [视觉与页面基准](references/visual-and-rendering.md)，复用 `assets/frontend-template` 的当前四页实现。只改业务差异，不把源模型路径、旧设备 ID、工厂名称、演示事件或发布身份带入新项目。
5. 本地启动 `node server.mjs`，默认地址 http://127.0.0.1:4173/，其他端口通过环境变量 PORT 指定。

## 页面与交互闭环

- 运行总览：全屏可交互模型为背景，左右数据层无外框卡片；环境、能耗、状态、趋势、事件和独立动画来自统一运行时状态。用电参考条为大圆角，参考量程可配置。
- 设备监控：浅灰全页，左侧分类、右侧全部设备卡片和搜索；卡片“查看设备”为蓝色圆角按钮，悬停略浅，进入设备详情。
- 设备详情：顶部主标签区替换为“返回设备列表”，返回保留分类和列表位置。只显示当前设备完整模型，静态结构保留，初次进入不选中。左侧是本机动画与“设备部件”，不显示“所选设备 · 独立动画”标题；右侧滚动展示全部设备参数、统计、阈值、事件和模型信息，右下视角/显示固定且不随信息滚动。
- 部件列表和“部件标注”只列原生动画部件组。按动画通道分组，一个组可驱动多个源节点，不按 AMI 名称前缀猜测；点击任一组显示对应标签并近看，关闭全部标注后仍显示当前查看组。无动画时明确显示无内置动画，不捏造动作。
- 告警中心：详细事件卡片按最短列瀑布流排列；宽度≤1920px 为2列，>1920px 为4列。展开、收起、筛选和窗口变化后重排，故障标签红色；保留触发值、阈值、快照、确认及恢复时间。

## 必须保持的行为

- 模拟数值持续更新；总数、状态、曲线、详情、事件与导出统一取自同一数据源。功率、电流、转速、振动、能耗要关联；零转速不能持续出现运行高振动，日用电按经过时间积分并跨日清零。设备参数和保护阈值仅为演示假设，不能冒充铭牌或现场测量。
- 确认仅标记事件已读，不解除当前异常；持续异常不重复建同一事件，恢复保留历史。切到真实源后清除模拟数据；断线显示离线，不能静默退回模拟。
- 每段原生动画独立播放、暂停、复位、倍速和进度；总览批量按钮作用全模型，详情批量按钮只作用本机。均为白底8px圆角纯文字，悬停仅文字蓝色。两页倍速控件使用同一透明无边框样式，完整显示0.25×等选项。
- 预警和故障外观一致：模型红色着色＋明显、紧凑的红色外发光，**没有描边**。不要恢复旧的2px/3px红线或整场 Bloom。正常选中才用3px纯白轮廓及浅蓝光晕，异常优先。恢复/离线还原缓存材质。
- 使用原始落地基准；glTF 为 Y-up，建模 Z=0 需核对根变换。不要按运动部件包围盒最低点抬起模型。接影面与零面吻合，已有地坪时避免重复共面，透明罩壳不写深度、不投实心阴影，离屏遮罩不更新阴影贴图。
- 未识别材质保留原外观。金属、喷漆、玻璃、橡胶分开配置，不能统一金属化。曝光为渲染配置，不显示曝光调节控件。

## 验证与交付

运行 `node "<SKILL_DIR>/scripts/check-project.mjs" "项目目录"` 和 `node --check dist/app.js`。按实际改动验证模型载入、设备/动画完整绑定、数据范围及积分、异常恢复、详情隔离与返回、部件标签、告警瀑布流及筛选。

在1920×1080与2560×1440、100%缩放下读取真实计算样式并截图：最小字体11px（含图表、说明和弹窗），侧栏无横向溢出，首尾卡片能完整滚动到位，固定视角区不被遮挡。设备较多时用明确分页/分组/滚动；原生动画很多时将轨道列表限高滚动，确保底部按钮可达，不声称无限内容同时一屏显示。

交付本地地址、启动方式、配置入口及模拟/真实状态；默认不初始化 Git、不上传 GitHub、不发布客户模型。只有用户明确提出后才执行相应外部流程。

视觉校准以[视觉与页面基准](references/visual-and-rendering.md)和随附前端模板为准。本分发目录不附带客户模型或设备截图；验收截图应在用户授权的项目中生成。
